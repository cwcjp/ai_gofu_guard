Gofu Guard v1.0.1

護符方式ガード実証
はじめての使い方

専門知識がなくても、AIに原則文書を読み込ませて試すことができます。

最初にお読みください

これはAIの応答や判断を改善するための試用手順です。AIに文書を読ませるだけでは、原則遵守や安全性は保証されません。外部操作を強制的に制限するGuard Gatewayは、現時点では未実装です。

① 一般利用者：ファイルを添付② ChatGPTのプロジェクト③ カスタム指示④ 技術者：Gitと実装よくある質問

① 一般利用者：ファイルを添付して試す

  1. 護符方式のGitHubページを開きます。
  2. 画面上のCode → Download ZIPを選びます。
  3. ダウンロードしたZIPファイルを展開します。文書が v1.0 などのフォルダー内にある場合は、そのフォルダーを開いてください。
  4. 次の3つの文書を探します。
    01_principles_v1.0.1.md
    02_governance_v1.0.1.md
    03_guard_implementation_v1.0.1.md
  5. ChatGPTなどのAIで新しい会話を開き、3文書を添付します。添付操作は利用するサービスにより異なります。
  6. 下の「最初の指示」をコピーして送信します。
  7. AIから「読み込めた範囲」「適用できない点」の説明を受けてから、普段の質問を試してください。

最初の指示（コピー用）

添付した「護符方式ガード実証」v1.0.1の3文書を、この会話での作業方針と検証対象として参照してください。

1. 文書を読めた範囲と読めなかった範囲を先に報告してください。
2. 外部システム・第三者・資産・情報・物理環境への影響可能性を実行前に確認してください。
3. 権限がない操作や不明な操作は迂回せず、停止または確認してください。
4. タスクの完了と会話・処理の終了を区別してください。
5. 結果を「完了／未完了／保留／中止」で示し、停止時は「不可能／実行不能／権限不足／その他・原因未確定」を区別して、根拠、残る作業、再開条件、残留リスクを説明してください。
6. 過去の回答や仮説を無条件に正しいとせず、事実・推測・未確認事項を区別してください。
7. サービスの上位指示・利用規約・実際の権限と衝突するときは、それらを優先し、衝突を説明してください。

これは安全制御の技術的保証ではありません。まず理解した内容と適用できない点を短く説明してください。次の依頼があるまで外部操作はしないでください。
まず試すなら：文章の要約や調査など、外部システムを変更しない作業がおすすめです。「どこまで確認できた？」「何が未確認？」と追加で尋ねてみてください。

② ChatGPTのプロジェクトで使う

毎回文書を添付したくない場合の方法です。ChatGPTで新しいプロジェクトを作成し、上記3文書をプロジェクトの資料として追加します。プロジェクトの指示欄には「このプロジェクトでは添付した護符方式v1.0.1の文書を参照し、読めない場合は明示すること」と記載してください。

そのプロジェクト内で新しい会話を開き、①の「最初の指示」を送って読み込み状況を確認します。資料が登録されていても、毎回すべてが正確に参照される保証はありません。

③ ChatGPTのカスタム指示で使う

日常の会話でも簡単な原則を意識させたい場合は、ChatGPTの設定にある「カスタム指示」に、次の短縮版を登録する方法があります。画面名や文字数制限は変更される場合があります。 

私は「護符方式ガード実証」の考え方に沿った応答を希望します。
タスクの完遂を絶対視せず、権限不足や重大な不確実性があれば迂回せず確認・停止してください。外部への影響を実行前に考慮し、事実・推測・未確認事項を区別してください。過去の自分の回答を無条件に正しいとせず、処理終了とタスク完了を区別してください。停止した場合は理由、未完了事項、再開条件、残留リスクを示してください。必要に応じて、以下のGitHubリポジトリにある正式文書を参照してください。原文を参照できない場合は、参照済みと主張せず、確認できた範囲で対応してください。

業務別の安全仕様を追加する

サーバー管理、経理、顧客対応などの業務で利用する場合は、業務固有の権限、禁止事項、停止条件、異常時対応を記した追加文書を作成してください。共通の3文書と合わせてAIに参照させます。業務別仕様で共通原則の禁止事項や権限境界を解除することはできません。

AIに追加文書の草案を作らせることはできますが、採用・承認は権限を持つ人間が行ってください。

④ 技術者：Gitで取得して実装・検証する

git clone https://github.com/cwcjp/ai_gofu_guard.git
cd ai_gofu_guard
  1. 01・02文書で原則と承認・報告条件を確認します。
  2. 03文書に従い、隔離された検証環境で対象操作を限定します。
  3. AIが実行先へ直接アクセスできない構造を用意し、独立したGuard Gateway相当の制御を設計します。
  4. 拒否・権限不足・迂回・故障時のfail-close・部分実行・残留作用を試験します。
  5. 実行状態、停止原因、根拠、残留リスク、判断主体を記録します。
このリポジトリは設計文書の公開が中心です。Gitで取得するだけでGuard Gatewayが導入されるわけではありません。顧客データや本番認証情報を使った初期試験は避けてください。

よくある質問

Markdown（.md）とは？

文章を記述するためのファイル形式です。GitHub上で内容を読むことも、AIにファイルとして添付することもできます。

AIに「記憶して」と頼めば、ずっと有効？

いいえ。会話、モデル、設定、プロジェクトを変えると適用状況も変わり得ます。新しい会話では読み込みと適用範囲を確認してください。

使うとハルシネーションが減りますか？

不確かな情報の断定や、過去の回答への過度な依存を避けるよう促す内容を含みますが、改善効果は未検証です。正答率の向上や安全性は保証しません。

使ってみた感想や問題点はどこへ？

GitHubのIssuesで報告できます。再現条件、期待した結果、実際の結果を書くと役立ちます。個人情報・機密情報・認証情報は投稿しないでください。
