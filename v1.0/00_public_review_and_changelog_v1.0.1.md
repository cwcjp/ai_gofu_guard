## 1. プロジェクトの目的

「護符方式ガード実証」は、AIエージェントの能力を活用しながら、権限逸脱、意図しない外部作用、停止・終了判断の混同などを防ぐための**運用原則と外部強制機構**を検討するプロジェクトです。

AIが指示を理解して守ることだけに依存せず、実行経路に置いた独立したガードによって、許可されない作用を遮断する設計を目指します。現時点で安全性を保証するものではありません。

## 3. v1.0.1の主な整理点

2026年9月28日時点のv0.2.0 Draft三文書を直接の改訂基準として、既存の21原則の番号と見出しを維持し、次の論点を明確化しました。

1. **外部影響の事前判定:** 外部システム、第三者、資産、情報、物理環境への影響可能性を実行前に評価する。影響判定は実行許可そのものではない。
2. **タスク完了と終了の区別:** 応答や処理の終了を、依頼された成果の達成と同一視しない。
3. **実行状態と停止原因の区別:** `完了／未完了／保留／中止`と、`不可能／実行不能／権限不足／その他・原因未確定`を区別し、根拠と判断主体を報告する。
4. **安全な停止と残留作用:** 新しい作用の遮断だけでは、進行中の外部作用や残留リスクの解消を意味しない。
5. **業務別安全仕様との分離:** 金融取引などの個別業務に固有の中断、復旧、補償、継続条件は、共通原則から分離して定める。
6. **人間の最終判断と外部ガード:** 権限ある人間による判断と、AIが迂回・書換えできない外部の制御機構を区別する。

既存の暫定補助原則（資料の量・反復・多数説と事実認定の区別など）は、文書の版が上がったことだけを理由に正式昇格させていません。

## 6. 公開レビューで検討してほしい論点

- **権限境界:** AIが外部ガードを迂回したり、別経路で同等の作用を実現したりできないか。
- **停止後の安全:** 処理中断後の外部作用、部分実行、重複再試行、不可逆な変更をどう扱うか。
- **判断と証跡:** 完了・停止・安全確認の根拠と判断主体を、後から検証できるか。
- **実装可能性:** allowlist、権限分離、監査ログ、ガード故障時の遮断を限定的なPoCで実現できるか。
- **運用上の副作用:** 過剰停止、承認疲れ、モデル間の解釈差、人間側の誤判断をどう評価するか。
- **原則自体への反証:** 原則間の矛盾、過不足、業務別安全仕様との境界の不明瞭さがないか。
